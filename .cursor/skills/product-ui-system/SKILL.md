# Product UI System

Muse Character Studio 是一间黑房间里的角色工作室。角色图承担色彩，控件保持近黑冷灰，深色下主按钮反白。焰蓝只用于焦点、当前项和进度。不要退回大面积灰白管理台，也不要加紫色渐变或满屏发光。

业务契约、字段和能力边界以 `docs/DESIGN.md` 为准。视觉和交互以 `docs/DESIGN_SYSTEM.md` 为准。Token 和壳层样式只写在 `client/src/theme.css`。

## 先看再改

1. 确认页面属于角色库、工作台还是系统。不要新造第四种壳。
2. 复用 `client/src/components/ui.tsx` 的按钮、字段、对话框、空状态。
3. 图标只加在 `client/src/components/icons.tsx`，保持 1.6px 描边。
4. 不改 `api.ts` 的动作入参，不用假数据替换服务端结果。

## 应用壳

- 视口锁定。新页面放进 `Shell` 的主区域，不要让 `body` 滚动。
- 侧栏是全局导航。分区导航放在工作台左侧。对象操作放检查器。
- 主内容、侧栏、检查器各自滚动。父级 `min-height: 0`，滚动容器 `overscroll-behavior: contain`。
- 窄屏：侧栏变抽屉（800px），检查器变右侧面板（1080px）。不要出现横向滚动条。

## 页面怎么选结构

- 角色库保持封面网格。角色是图片，不要改成无图表格。
- 设定、生成、画廊、参考素材留在工作台分区里。不要把长表单放进小对话框。
- 大图和只读整合文本用对话框。删除和归档用确认对话框。
- 系统页用标题、说明和表格，不要再包一层指标卡。

## 状态

每个操作都要有结果：按钮在等待时禁用并改文案，成功和失败都进入提示。失败文案包含原因。角色名可以换行，不要截断。

## 动效

跟随 `theme.css` 里的 `--ease-out` 和时长。按下用 `scale(0.98)`。对话框从 0.98 进入。命令面板不动画。尊重 `prefers-reduced-motion`。不要给每次切页加位移动画，不要用毛玻璃和装饰渐变。

## 不要

- 不要把所有页面做成同一种卡片栅格。
- 不要用紫色渐变、全页阴影、统一大圆角或毛玻璃来制造质感。
- 不要新增一套平行的颜色变量。缺的层级补进 `theme.css` 的现有角色。
- 不要为了界面统一，把训练式的多步任务硬塞进检查器。当前产品没有这种流程；真出现时用整页步骤，而不是小抽屉。
